## 1. 本轮修掉的 5 个真 bug

| # | 现象 | 根因 | 修法 | 证据 |
| --- | --- | --- | --- | --- |
| 1 | DLL 栈窗口每个 CallDLL 平移 | 入口 `reallive_dll_func_call` 是 stdcall（出口 `retl $0x14` 已清参数），执行器返回后又补 `esp += argc*4` → 每次调用 `esp` +20 字节 | `emu_run()` / `RUN_EXPORT` 保存并复位 `esp`，不平衡时告警 | 真机 8963 次调用后 `esp` = `0x10200000 → 0x1022bc40`（20×8963 ≈ 0x2BC3C）；夹具仍 280/280 |
| 2 | 固定帧死循环（`10004932..42`），每次 `步数上限 200000000` | `cmp r32, r/m32`（opcode `0x3B`）寄存器形式把第二操作数截断成低 16 位 → `cmp %ebx,%eax; jne` 在两边都是堆指针时永远不等 | 只有 `opsize16` 才截断；加指令级回归自测 | 观察点现场：`eax(begin)=0x11406E60`、`ebx(pos)=0x11406E64` 只差 4 字节，而中止时 eax 已 +99,999,792（= 4 × 24,999,948 次迭代） |
| 3 | 小游戏能画但逻辑不推进 | x87 `DA` 组（m32int 整数算术）整族未实现 → 每次撞上 `0x100033ED`（`da 46 4c` = `fiadd dword [esi+0x4c]`）就 UNIMPL，整个 CallDLL 被中途放弃 | 实现 `DA /0../7`；修正 `DE` 组内存形式（原来 `reg==0` 只做 `fp_pop()`，会毁 x87 栈）；补 `FIST m32` | 真机日志 221 次 `未实现指令 x87 @ 100033ed`；自测 `4+4 → 8` PASS |
| 4 | 第一场结束后第一句对话：画面冻结、音乐正常、进程 187% CPU，stdout 55Hz 刷 `Unknown Gameexe key 'WINDOW.032.XXX'` | `TextWindow` 构造函数读 `WINDOW.<i>.ATTR_MOD` 等键；汉化版 GAMEEXE.INI 只给 000..010/012..014 写全属性，小游戏用的 020/021/031/032 缺键 → RLVM 抛异常（原生引擎取默认值）→ 窗口构造失败、永不进缓存 → 阻塞 op（`Msg 17 = pause`）永不完成 | 平台层补键：对数据里真实存在的窗口补齐没有默认值的那些键，值照抄窗口 000，注入走 `Gameexe::parseLine`（见 D-037） | 冻结时 `rlvm-font: text window #32 colour after ctor` 证明构造成功；55Hz 异常消失 |
| 5 | 修完 #4 后改成崩（`exited cleanly (132)`，无 tombstone） | 上游 `TextWindow::Render` 在 341/449 行先解引用 `namebox_waku_`，443 行才判空；而 `namebox_waku_` 只在 `NAME_MOD==1 && NAME_WAKU_SETNO 存在` 时创建 → 窗口 032 没有 `NAME_*`，一旦文本带说话人名就空指针 | 把 `NAME_MOD / NAME_WAKU_SETNO / NAME_MOJI_REP / NAME_MOJI_POS / NAME_POS / NAME_MOJI_SIZE` 纳入补键范围（值照抄窗口 000） | tombstone：`#00 TextWindow::GetNameboxWakuRect()+76` ← `#01 TextWindow::Render()+616` |

**顺带修掉的取证设施 bug**（不是游戏 bug，但坑了很久）：

* 执行器 SIGSEGV 兜底处理器原来直接 `_exit(132)` → 把 tombstone 一起吞掉
  （真机只看到 `Zygote: Process N exited cleanly (132)`，看起来像"正常退出"）。
  现在链回原处理器（bionic/ART 那个才会去叫 debuggerd）。
* 处理函数运行期间本信号被自动屏蔽，`raise(sig)` 只会排队再落到兜底 `_exit`
  → 必须先 `sigprocmask(SIG_UNBLOCK)`。
* API 31 没有 `backtrace()`（API 33 才引入）→ 改用 `_Unwind_Backtrace` + `dladdr`
  输出模块内偏移（`[pt00] HOST BT: ...`），本机用未 strip 的 `librlvm.so` 符号化。

## 4. 真机取证开关速查（改 `rlvm-diag.txt` 后 push，不用重编）

| 键 | 作用 |
| --- | --- |
| `lb_minigame=1` | 不跳过小游戏 + 打开 `[pt00]` 调用日志 |
| `pt00_trace_ctx=1` | 记录 intD / ctx 的读写（配合读环） |
| `pt00_watch=<hex>` | 观察点：每次 CallDLL 首次命中该 eip 记录寄存器 + `[edi-0x10..+0x1c]`，步数上限时整环转储 |
| `pt00_verbose=1` | 逐调用日志（默认关：logcat 同步 I/O 会把小游戏拖慢） |

现成文件：`tools/rlvm-diag.pt00-watch.txt`；执行器侧关键字：
`[emu] WATCH 环` / `[emu] INTD 读环` / `[emu] mem edi-0x30` /
`[emu] 调用前后 esp 不平衡` / `[pt00] HOST FAULT` / `[pt00] HOST BT`。
